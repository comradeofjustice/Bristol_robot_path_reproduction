# 轨迹复现：Pololu 3Pi+ 与 Processing 数字孪生

两套独立工程来自 [课程原始模板](https://github.com/paulodowd/RoboticsScienceAndSystems)，采用提交 `2dd585408a3e0a2f389c8e56dc42f4b960d3cb71`。Arduino 工程保留模板的 I²C 底盘接口和欧拉里程计；Processing Java Mode 工程保留模板的线性电机模型和欧拉模型。两边均以驱动轮中点为位置参考：初始前方为 +x，左侧为 +y，逆时针为正角度。

| 工程 | 打开方式 |
|---|---|
| `PathTwin/PathTwin.pde` | Processing 4 → Java Mode → Run；运行结束后生成 `PathTwin/sim_run.csv`，按 R 重播 |
| `PathRobot/PathRobot.ino` | Arduino IDE → M5Stack → M5StampC3；USB CDC On Boot **Disabled**，上传速度 **115200**，串口监视器 **9600 baud** |

## 实验设计

这是可重复的开环输入实验：对两套系统发送相同 PWM 和时长，检验得到的轨迹是否一致。没有位置反馈补偿，避免控制器把待观察的电机与几何差异掩盖。时序来自 `PathTwin/data/path.csv`；编辑后在本目录执行 `python3 sync_plan.py` 更新 Arduino 的 `PathPlan.h`。两端控制周期名义 10 ms，日志目标间隔 50 ms。仿真以固定时间步运行，实机用实际毫秒时间，保留采样时刻的波动。

| 阶段 | 时间（s） | 左/右 PWM | 观察重点 |
|---|---:|---:|---|
| 低速直线 | 0–2.0 | 60 / 60 | 左右不对称、起步延迟 |
| 加速直线 | 2.0–3.5 | 100 / 100 | 是否符合线性 PWM–轮速关系 |
| 停车 | 3.5–4.0 | 0 / 0 | 停车后的残余运动 |
| 左圆弧 | 4.0–6.0 | 45 / 95 | 圆弧的偏差、内外轮速度差 |
| 原地转向 | 6.0–7.0 | −60 / 60 | 角度误差和中心平移 |
| 旋转微调 | 7.00–7.05 | −62 / 62 | 仿真车头接近 180° |
| 水平倒车 | 7.05–8.65 | −65 / −65 | 理想轨迹沿 +x；实机可能跑偏 |
| 停稳 | 8.65–9.65 | 0 / 0 | 最终位姿 |

## 实机采集

1. 先在车轮悬空时上传并验证停止和正反转。实测时使用平整、空旷的地面，开启底盘电池电源。USB 数据线应有余量，避免牵拉机器人。
2. 在地面标记初始轴和轮轴中点。固定俯拍相机，拍到整条路线和同一平面的比例尺或标定点；在车体上标出轮轴中点及正前方，方便逐帧读出位置和角度。先摆好机器人并开始录像，再给 StampC3 上电或复位。StampC3 每次启动后等 3 秒，自动尝试运行一次；如果通过 USB 保持供电，切换底盘电源不一定会重启 StampC3。顶部绿灯亮起是与命令起点接近的视频对齐标记；记录对齐误差（至少受一帧间隔影响）。倒计时期间发送 `x` 可取消，运行中发送 `x` 可提前停机。
3. 机器人会自动停止。停止后串口才输出整次日志，避免 9600 baud 影响运动调度。复制一份完整的 CSV 表头和数值行，保存为 `results/robot_trial01.csv`，并保留原始监视器日志。检查 `# RUN_END complete` 和最后的 `done` 行。失败或提前中止的试次单独留档。
4. 用外部测量提取时间、轮轴中点的 x/y 及车体朝向，保存为 `results/video_trial01.csv`（表头 `t_ms,x_mm,y_mm,theta_rad`）。t=0 对应绿灯开始，角度用弧度并连续展开，y 轴向左；不要把屏幕像素 y 向下直接当实验 y。每段至少有若干点，推荐 20 Hz 或更高，并保留运动结束后的观测。记录标定尺度、视频帧率、误差和任何缺帧。建议同一条件至少重复五次，保持电池、地面、起始位姿一致。
5. 在 `results/trial_metadata.csv` 中记录试次条件。初始模板为轮半径 16 mm、轮距 90 mm、358.3 计数/圈。如实测校准了几何参数，应在记录中注明，不要把验证试次用于调参。

## 比较与解释

在本目录执行（前两条命令分别生成不同对照，互不覆盖）：

```sh
python3 compare_runs.py PathTwin/sim_run.csv results/robot_trial01.csv --out results/trial01_odom
python3 compare_runs.py PathTwin/sim_run.csv results/video_trial01.csv --kind external --out results/trial01_video
```

可加 `--plot` 输出轨迹与误差图，需要 matplotlib（`python3 -m pip install matplotlib`，建议在虚拟环境中安装）。可用 `--threshold-mm`、`--threshold-deg` 设置首次可观测偏离阈值；默认是 20 mm 或 5°，如现场测量噪声较大，先根据重复静止测量确定阈值。脚本只对共同覆盖的时刻做插值，不外推，不跨越超过 250 ms 的数据缺口。

- `aligned.csv`：逐时刻位置和有符号航向误差。
- `segments.csv`：每段位置/航向 RMSE、最大误差，以及每段重新对齐后的最大偏差。
- `summary.txt`：首次超过阈值的时间和阶段、段内偏差最大的运动。
- 区分“仿真 vs 实机编码器估计”和“仿真 vs 独立物理轨迹”。即使编码器估计一致，也可能发生打滑。还可把实机编码器 CSV 作为第一输入、视频 CSV 作为第二输入，比较编码器自身的误差；绘图中的第一条曲线代表传入的第一份日志。

如果原地转向后累计误差最大，检查该段重新对齐后的误差；如果倒车只有累计误差大，可能主要是继承前段航向偏差。用停稳段检验模型的瞬时停止假设，用两档直行测量速度检验线性假设，再用原地旋转检验有效轮距。电压、静摩擦、打滑、I²C 和采样时序均是待验证的解释，不凭曲线形状认定原因。

## 当前已验证的基线

Processing 4 实际运行了 9.65 s，导出 194 条样本。仿真在低速直行结束时为 x=150 mm，加速直行结束时为 x=337.5 mm；圆弧结束时 θ≈79.6°。原地旋转加上 50 ms 微调后，倒车起始朝向为 180.0040°，倒车沿 +x 移动约 130.0 mm，横向仅变化 0.0085 mm。最终 **(591.78 mm, 102.78 mm, 180.0040°)**。见 `results/simulation_baseline.png`。由于课程电机模型不含惯性，仿真停车段位姿不变。尚无实机运行和外部测量，不能报告实测偏差。
